# LATM library interface tests

Tests for the direct LATM/LOAS decoding interface of libfaad:

- `NeAACDecInitLATM` — initialise the decoder from a LATM/LOAS stream
  (AudioMuxVersion 0 and 1),
- `NeAACDecLatmFeed` / `NeAACDecLatmDecode` — streaming interface: feed
  arbitrary byte slices, pull decoded frames.

## Running

Build the library and the frontend first:

```sh
cmake -B build -G Ninja
cmake --build build
sh test/run_tests.sh build
```

The suite checks, for the fixed samples in `samples/`:

1. the same LATM stream decoded through the LATM entry points, through the
   existing `NeAACDecInit`/`NeAACDecDecode` entry points, and through the
   `faad` frontend produces bit-identical PCM;
2. feeding the stream in arbitrary byte slices (1, 2, 3, 5, 7, 13, 64, 255,
   1024, 4096, whole-file) produces bit-identical output;
3. malformed headers (`samples/m_*.loas`) fail deterministically with the
   same error on repeated runs.

## Samples

- `tone.adts` — source AAC-LC stream (`ffmpeg -f lavfi -i sine=... -c:a aac`)
- `tone_v0.loas` / `tone_v1.loas` — the same AAC frames wrapped in
  LATM/LOAS, AudioMuxVersion 0 and 1. Generated by `adts2latm.py`:
  `python3 test/adts2latm.py test/samples/tone.adts test/samples/tone_v0.loas 0`
- `m_*.loas` — malformed streams (bad sync, audioMuxVersionA, unsupported
  mux configuration, CELP frame length type, zero frame length, truncated
  config, corrupt mid-stream element). Generated by `gen_malformed.py`:
  `python3 test/gen_malformed.py test/samples test/samples/tone.adts`

`latm_test.c` is the test harness; see its header comment for the modes.
